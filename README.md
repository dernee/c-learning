# C 语言修仙在线练习

一个**纯前端、零后端、零依赖**的 C 语言学习网站。双击 `index.html` 即可运行，也可以一键部署到 GitHub Pages。

核心玩法：写一段 C 代码 → 点运行 → 右侧柱状图**逐帧动画**演示数组每一轮循环的比较与交换；同时还能刷题赚积分，从**炼气期**一路修到**道祖**。

## 一之二、1000 道大题库说明

题库来自《C语言程序设计题库1000题》，按 **25 个章节**组织，覆盖从语法基础到文件、综合编程的完整链路。

> **关于代码完整性**：原始 docx 里有 5 道题的代码本身就没写完
> （4 道编程题的参考程序中途被下一题的标题打断、1 道阅读题只剩一行数组声明）。
> 这些代码用户复制去编辑器会直接报错，已在 `tools/parse_bank.py` 里按题干要求补全为
> 可运行、结果与标准答案一致的标准代码，并在解析里标注了补全说明。
> `parse_bank.py` 现在会自动检测「括号不闭合」和「编程题缺 main」，重新导入新题库时能立刻发现同类问题。

## 二、本地运行

**方式 1：直接双击（最快）**

双击 `index.html`，用 Chrome / Edge 打开即可。全部功能可用，无需服务器、无需联网。

**方式 2：起一个本地静态服务器（推荐，避免个别浏览器的本地文件限制）**

在 `c-practice` 目录下执行任意一条：

```bash
# Python
python -m http.server 8080

# Node
npx serve -l 8080
```

然后访问 <http://localhost:8080>。

> 提示：请务必保持目录结构不变（`css/`、`js/` 与 `index.html` 同级）。项目用的是相对路径，散开目录会导致样式和脚本 404。

1. 进入仓库 → 顶部 **Settings**

## 四、如何新增题目

所有题目都在 `js/questionBank.js` 的 `questions` 数组里。**在数组末尾 push 一个对象即可，页面会自动读取，不需要改任何其他文件。**

### 选择题

```js
{
  id: 'q23',              // 唯一编号，不要和已有的重复
  type: 'choice',
  diff: 2,                // 难度：1 入门 / 2 进阶 / 3 困难（只影响标签颜色）
  point: 10,              // 答对获得的积分，直接决定修仙进度
  stem: '以下哪段代码能正确<strong>释放</strong>动态申请的内存？',
  options: ['free(p);', 'delete p;', 'p = NULL;', 'release(p);'],
  answer: 0,              // ★ 正确项的下标，从 0 开始（这里 0 = 'free(p);'）
  hint: 'C 用 free，不用 delete。',
  explain: 'malloc 申请的内存在 C 中用 <code>free(p)</code> 释放，free 之后应立刻把指针置空以防悬垂指针。'
}
```

### 代码填空题

```js
{
  id: 'q24',
  type: 'fill',
  diff: 2,
  point: 15,
  stem: '补全快速排序的一趟划分循环条件。',
  code: 'for (i = 0; ____; i++) {\n    if (a[i] < pivot) swap(a[i], a[low++]);\n}',
  blanks: [
    { id: 'b1', label: '第 1 空', answer: 'i < n' }
  ],
  hint: 'i 要从 0 遍历到数组末尾。',
  explain: '一趟划分需要 i 从左到右扫完整个数组，因此条件为 i < n。'
}
```

填空题在 `code` 里用 `____`（四个下划线）标记空位，`blanks` 按**从左到右**的顺序给出每个空的参考答案。判分时会自动忽略首尾空白与多余空格，`i<n` 和 `i < n` 都算对。

### 三个注意事项

1. `id` 必须唯一，否则重复刷题判定会串。
2. `type` 只有 `'choice'` 和 `'fill'` 两种，其它值会渲染异常。
3. 题库里 `answer` 是明文。这是纯前端学习项目的固有特性（浏览器里任何 JS 都能被看到）；如果要做成正式考试系统，需要把判分放到服务端。

改完直接刷新页面（`Ctrl + F5` 强制刷新缓存）就能看到新题。

## 五、如何修改修仙等级积分

所有境界规则都在 `js/scoreCalc.js` 顶部的 `LEVELS` 数组里，**只改 `min` 字段就能调整整个游戏的进阶节奏**。

```js
const LEVELS = [
  { name: '炼气期', en: 'Qi Refining', min: 0,    color: '#94a3b8', glow: 'rgba(148,163,184,.35)' },
  { name: '筑基期', en: 'Foundation',  min: 100,  color: '#34d399', glow: 'rgba(52,211,153,.35)' },
  // ...
  { name: '道祖',   en: 'Dao Ancestor', min: 1000, color: '#ffffff', glow: 'rgba(255,255,255,.65)' }
];
```

- **规则**：数组必须**从低到高**排列，`min` 是该境界的**起始积分**。当前境界 = 最后一个满足 `min <= score` 的项。
- **改门槛**：想把筑基期从 100 分改成 150 分，就把它的 `min` 改成 `150`。
- **加新境界**：在数组中间插一项即可，例如在结丹期和元婴期之间插入 `{ name:'金丹期', en:'Golden Core', min: 138, color:'#a3e635', glow:'rgba(163,230,53,.35)' }`。等级阶梯面板、顶栏迷你面板会自动多出一格。
- **改颜色**：`color` 是主色，`glow` 是光晕（`rgba`）。道祖这类高境界建议给亮色系，视觉上更有压迫感。

### 顺带可以调的计分参数

| 想改什么 | 位置 | 说明 |
|---|---|---|
| 某题的分值 | `questionBank.js` 的 `point` | 单题分值 |
| 连对额外奖励 | `scoreCalc.js` 的 `bonusTable` | `[0,0,2,3,5,8,12]` 对应连对 1~6 题的额外加分，用满后恒定 +12 |
| 重复刷已答对的题 | `scoreCalc.js` 的 `isRepeat` 分支 | 目前只给 1 分，防刷分 |
| 存档保留记录条数 | `scoreCalc.js` 的 `MAX_RECORDS` | 默认 30 |
| 存档键名 | `scoreCalc.js` 的 `STORAGE_KEY` | 改它相当于**清空所有进度** |

> 进度存在浏览器 `localStorage`（键 `c_practice_score_v1`）。换浏览器/无痕模式/清理缓存都会重置；隐私模式下若存储不可用，会自动降级为内存计分（刷新即丢，但功能不报错）。等级面板底部有「等级规则」和「重置」两个按钮——「重置」会清空全部进度，操作前会二次确认。

## 六、功能说明

### 刷题模式
- 22 道题，涵盖基础语法、数组、指针、函数、排序算法、常见陷阱
- 选择题点选项即判，代码填空题支持多空
- 提交后展示答案解析，自动计分、连对加成、升级特效
- 记录已答过的题（换着刷，避免重复得分）

### 可视化演示模式
- 左侧编辑 C 代码（带行号 + 语法高亮），右侧柱状图实时动画
- 播放控制：**运行可视化 / 暂停 / 单步 / 重置**，速度四档（0.5x 慢速 → 4x 极速）
- 统计信息：比较次数、交换次数、当前轮数
- 实时变量表：把 `i`、`j`、`n` 等所有标量变量逐轮刷新
- 执行日志：逐条打印「比较 a[0]=29 > a[1]=10 → 交换」这类事件
- **交互式控制台**：像 Visual Studio 那样和程序对话（详见下节）
- **交换示意动画**：需要交换时两根柱子抬起、点亮、再落下（详见下节）
- **代码实时联动**：编辑器高亮当前行 + 下方浮层显示该行原文与变量当前值
- 内置 7 个示例：3 个交互程序（猜数字 / 计算器 / 成绩统计）+ 4 个排序可视化

### 交互式控制台（像 Visual Studio 那样和程序对话）

代码里只要用了 `scanf` / `input` / `getchar`，程序运行到那里就会**自动暂停等你敲键盘**：

```
第 1 次猜测，请输入 1~100 的整数：  ← 程序输出
┌─────────────────────────────────────┐
│ ⌨ 程序需要输入，请在此输入后按回车    │  ← 黄色提示条自动弹出
├─────────────────────────────────────┤
│ » 50█                                │  ← 光标自动定位到这里，直接打字
└─────────────────────────────────────┘
```

| 操作 | 效果 |
|---|---|
| 直接打字 | 焦点已经自动落在输入框，不用鼠标点 |
| `Enter` | 把这行输入送给程序，继续执行 |
| `Esc` | 跳过本次输入（程序收到一个空值，相当于 C 的 `atoi("")` → 0） |

配套设计：
- **LED 指示灯**：等待输入时变黄闪烁，运行中变绿，一眼看出程序状态
- **用户输入会回显到终端历史**，对话过程完整可见
- **不会打断你写代码**：如果你正在编辑器里打字，就不抢焦点
- **程序等待时动画自动停**，不会在你思考时偷偷往下跑
- 换到刷题模式时会自动喂一个空值，程序不会卡死在那里

支持的输入写法：

| 写法 | 说明 |
|---|---|
| `scanf("%d", &x)` | 读一个整数（`&` 取地址已支持） |
| `scanf("%d %d", &a, &b)` | 同一行读多个，用空格隔开 |
| `scanf("%f %lf %c %s", ...)` | 浮点 / 字符 / 字符串都支持 |
| `scanf("请输入年龄：%d", &age)` | 格式串里的中文会作为提示语显示 |
| `input()` / `input("提示")` | 读一整行字符串并返回 |
| `input(name)` | 直接写进已声明的字符数组 |
| `getchar()` | 读一个字符，返回字符码 |

### 交换示意动画

需要交换两个数时，两根待交换的柱子会先被「抬起来」，再落下换位：

```
抬起并点亮 → 落位描边 → 数值互换（柱子高度变化）
```

- 抬起阶段：待交换的两根柱子变成琥珀色、微微上浮并放大，一眼看出是这两根
- 落位阶段：换成金色描边，提示即将换位
- 随后真正的数值交换由 swap 事件改柱子高度，柱体弹一下

**只在真正需要交换时才动**。顺序不对的比较（比如冒泡里 `a[j] <= a[j+1]`）只点亮两根柱子做高亮，不会白演一遍。

动画是**可打断的**：暂停、单步、重置、换示例都能在任意阶段生效。
中途停止时 `SwapFx.cancel()` 会**同步**清掉高亮状态 —— 不会出现「柱子还悬在半空」。

### 动画节奏：只在该看的地方慢放

解释器每执行一步都会产出一个事件，但**绝大多数步骤不改变画面**。
冒泡排序699 步里只有 47 步真正动了柱状图（声明数组 / 数组元素比较 / 交换 / 写入），
其余 652 步是执行行、变量赋值、循环变量比较、打印。

早期版本对所有步骤一律按用户选的速度等待（1x = 300ms/步），
等于 93% 的时间在干等 —— 用户盯着不动的柱子等十几秒才等到一次交换，
于是以为「动画没了」。

现在按事件分级：

| 事件类型 | 等待 |
|---|---|
| 有视觉变化（`array` /数组元素 `compare` / `swap` / `set` / `end` / `print`） | 用户选择的速度（0.5x ~ 4x） |
| 无视觉变化（`line` / `setVar` / `loop` /循环变量比较） | `speed/6`，上限 45ms |

1x 速度下跑完整个冒泡排序从约 210 秒降到 30 秒左右，
而每一次交换、每一处高亮仍然是慢慢展示的。

配套的动画细节：
- **柱子入场**：声明数组时逐根从地面弹起，按下标错开 45ms，形成波浪
- **比较脉冲**：正在比较的两根柱子呼吸式发光 + 数值轻微跳动 + 底部扫描光
- **交换弹跳**：柱子落地有回弹，顶部数值放大一下再缩回
- **完成波浪**：排序结束逐根点亮成绿色，从左到右扫过

> 同一对柱子会反复交换，所以每次都强制重启动画（`Viz.replay`先摘class 再强制回流），
> 否则只有第一次有弹跳，后面全是静默变高度。

### 像素剑光标

全站鼠标指针换成一把像素钻石剑（Minecraft 附魔钻石剑，SweezyCursors 包）。

![像素剑光标](assets/cursor-sword.png)

**规则集中在 `css/style.css` 末尾**，只有四条：

| 元素 | 光标 | 为什么 |
|---|---|---|
| `html, html *` | 剑 | 一次选中所有后代，以后新增任何 DOM 元素都自动继承，不会漏 |
| `input` / `textarea` | `text` | 保留 I-beam，否则用户看不出这里能打字 |
| `.qf-input` | `text` | 填空框，由 JS 动态创建，自身 class 特异性更高，需单独声明 |
| `.btn:disabled` 等 | `not-allowed` | 禁用态不变，避免误导用户以为能点 |

**为什么这一段必须放在文件末尾**：前面各类组件（`.btn` / `.qo-item` / `.ld-item` …）
各自都声明了 `cursor`，靠特异性谁赢很容易算错。放最后用「同特异性后来居上」，
不必逐个元素去抠。

**热点 `(5, 0)` 的含义**：CSS 的 `url() x y` 是图片内哪个像素对准鼠标点。
剑尖朝左上，所以热点设在剑尖 —— 鼠标点正好落在尖端，剑身向右下延伸，不挡视线。
取的是最上一行非透明像素的**中点**（剑尖是有宽度的斜切块，取最左像素会偏）。

**图片加载失败不会变空白光标**：每条 `url()` 后面都跟了 `default` / `not-allowed`
兜底关键字，图片挂了光标会退化成系统箭头。

**换图 / 换尺寸**：

```bash
python tools/make_cursor.py "路径/新图.png"
```

脚本会做四件事，然后打印出新的热点数值，复制进 `--cursor-sword` 即可：

| 步骤 | 原因 |
|---|---|
| alpha 阈值二值化 | 原图边缘有 `alpha=13` 的半透明像素，直接用在深色背景上会显出一圈灰边（"脏边"） |
| 定位剑尖 | 热点必须落在指向性位置，否则鼠标点不在剑尖上 |
| 缩到 64px | 浏览器光标上限 128px，但 128 的剑会挡住大片内容 |
| `NEAREST` 缩放 | 像素画必须整数倍缩放，插值缩放会把像素糊掉 |

> 原图 128×128、逻辑像素 8px，缩到 64 正好是 2 倍整，像素块 8px → 4px，依然锐利。

#### 为什么做成"寄生弹窗"而不是独立特效

这个形态改了三版，每一版都是被实际观感否掉的：

| 版本 | 做法 | 被否的原因 |
|---|---|---|
| v1 | `inset:0` 全屏居中 + 300px 角色 + 无限呼吸 | 挡住题目和代码区，答完题看不见自己选了什么；`infinite` 让画面一直躁动 |
| v2 | 挂在「答题反馈」条右上角，1 秒后消失 | 页面上**长期存在**一个特效图位，观感像"网站里嵌了一张图" |
| **v3（现行）** | 克隆一枚徽章塞进 `main.js` 自己弹的 toast 里 | 弹窗没了特效就没了，天然"用完即走" |

**为什么不自己再弹一个带特效的提示？** `main.js` 判分时本来就会弹
`toast('答对啦！', …)`，自己再弹一个用户会看到两个弹窗。所以改为"搭车"。

#### 怎么触发的：MutationObserver 监听弹窗

`main.js` 里的 `toast()` 是模块内私有函数，没挂到 `window`，包不到；
而 `Quiz.showResult` 挂钩又会在新旧两版之间反复横跳。所以最终方案是
**直接盯住弹窗容器 `#toastWrap`**，谁进来我给谁装徽章：

```javascript
const mo = new MutationObserver(muts => {
  for (const m of muts) for (const node of m.addedNodes) {
    if (node.nodeType !== 1) continue;
    if (!node.classList || !node.classList.contains('toast')) continue;
    const kind = node.classList.contains('ok')  ? 'ok'
               : node.classList.contains('err') ? 'bad'
               : null;              // warn / lv 等其他弹窗不挂特效
    if (kind) mount(node, kind);
  }
});
mo.observe(dom.wrap, { childList: true });
```

`mount()` 只做四件事：`cloneNode(true)` 克隆隐藏模板 → 随机化粒子方向 →
给弹窗加 `fx-host` 类让出左侧 62px → 两帧后统一挂 `go` 类触发动画。

**最大的好处：不需要任何清理。** 徽章是 toast 的子节点，toast `remove()`
时浏览器会把它一起带走，所以既没有 `setTimeout` 收尾，也没有"页面上残留
一个特效图片"的可能。`main.js` 一个字符都没改，删掉 `js/fx.js` 网站就恢复原样。

模板本体是 `display:none` 的 `#fxTemplate`，只作克隆素材源——它不参与布局、
不可见、也不会被 `tab` 聚焦。

#### 五个必须遵守的坑

| 坑 | 表现 | 原因 | 做法 |
|---|---|---|---|
| **同元素 vs 后代选择器写混** | 元素、素材、控制台全正常，**画面上什么特效都没有** | `fx-ok` 挂在 `.fx-badge` 上，爆炸框/对勾/粒子是它的**子节点**。写 `.fx-burst-ok.fx-ok.go`（同元素复合类）永远匹配不上 | 子节点一律写 `.fx-badge.fx-ok .fx-burst-ok.go`（后代）；只有徽章自身的入场/红闪才用 `.fx-badge.fx-ok` |
| **父级没有显式 `height`** | 头像被压成 1px 的一条线，同样零报错 | `.fx-char` 用 `height:100%`，而父级 `.fx-shaker` 若 `height:auto`，百分比高度退化成 0 | `.fx-shaker` 必须写 `position:relative; width/height:100%` |
| **同一元素挂两个 `animation`** | class 齐全、无报错，动画完全不动 | 多个动画作用于同一属性时由最后声明者输出 | 徽章只挂一条 animation，红闪改用 JS 定时切 `.fx-redflash` 类 |
| **用 `transform` 做居中** | 定位后动画整体静止 | `transform` 通道要留给 `scale/rotate` | 居中一律用 margin 负值 |
| **`display:none` 里的背景图不预取** | 第一次答对时头像晚半拍出现，有一下闪白 | 浏览器不为不可见元素拉资源 | `init()` 里显式 `new Image().src = 'assets/…'` 预热三张素材 |

前两条最坑：**它们都不报错，只是安静地不显示**。光看代码和 `classList`
完全看不出问题——只能靠量 `getBoundingClientRect()` 才暴露。所以测试里
专门加了"头像宽高 ≥30px""对勾 `opacity > 0.5`""粒子拿到了自己的颜色"
这几条断言来锁住它们。

另外 `void offsetWidth` 也重播不了动画（只强制重排，不保证时间轴归零），
统一用 `requestAnimationFrame` 等两帧再切 `go` 类。

#### 角色为什么做成圆形

```bash

对勾/叉号压在嘴部。这个位置是跟着素材尺寸调的（`.fx-mark` 的

动画和代码严格对应，两处同时显示：

1. **编辑器内**：当前执行行高亮，长代码会自动滚动跟随
2. **柱状图下方浮层**：
   ```
   ┌──────────────────────────────────────────┐
   │ 当前执行 │ 16│  i=2  j=0  if (a[j] > a[j + 1]) {

| 按钮 | 作用 |
|---|---|

**防误触设计**：「清空」和「重置」都会弹出确认框，因为两者都会不可逆地丢代码。

- 确认框会显示**即将删除的规模**（如「26 行 · 532 字符」），让你知道自己在删什么
- 默认焦点落在**「取消」**上，直接敲回车不会误删
- `Esc` / 点遮罩 / 点右上角 ✕ / 点「取消」**都算取消**，代码原样保留
- `Tab` 键被锁在弹窗内循环，不会 Tab 到背后的按钮上再回车
- 正在运行时点清空会先停掉动画，再复位全部状态（执行高亮、滚动位置、状态栏）

清空后编辑器是完全干净的空状态，可直接输入新代码运行；想找回默认代码点「重置」即可。

### 支持的 C 语法

```
数据类型    int / char / double / float / void，数组，指针（有限模拟）
语句        if / else / for / while / do-while / break / continue / return
运算符      + - * / % ++ -- == != < > <= >= && || ! & | ^ ~ << >> ?:
输入        scanf / input / getchar（交互式，会暂停等用户输入）
其他        函数定义与调用（含递归）、printf 格式化输出、sizeof
```

> 说明：这是**教学用的模拟编译器**，不是完整的 C 语言实现。指针支持 `*p`、`p++`、`p[i]`、`p-a`、`p = a+n-1` 等常见写法，但不追求完整 C 指针语义；`#include` 等预处理指令会被忽略。位运算按 32 位整数语义处理。
>
> `scanf` 遵循 C 标准的关键规则：格式串里的空白表示"跳过输入中的任意空白"，而 `%c` 默认**不跳**空白；`%s` 写入字符数组时自动补 `'\0'`。

## 七、常见问题

**Q：打开后页面空白 / 样式丢失**
A：确认 `css/` 、`js/` 文件夹和 `index.html` 在同一级目录下，且文件名大小写完全一致（Linux 服务器上大小写敏感，本地 Windows 不敏感但 GitHub Pages 敏感）。

**Q：点运行没反应**
A：打开浏览器控制台（F12）看报错。常见原因是 C 代码里用了模拟器不支持的语法（比如 `struct`、`typedef`、字符串拼接等），会给出明确的错误行号提示。

**Q：代码里有中文注释会不会解析出错**
A：不会，`//` 和 `/* */` 注释会被预处理阶段正确剥离。

**Q：动画卡顿**
A：把速度调到「慢速」，或减小数组长度。步数上限是 40 万步，超出会自动中止并提示。

## 八、技术栈说明

原生 HTML + CSS + JavaScript，**零第三方库、零构建工具**。C 解释器用的是「递归下降解析 + 生成器（generator）逐步产出执行事件」的结构 —— 生成器天然把执行过程切成一个个事件（`array` / `line` / `setVar` / `loop` / `compare` / `swap` / `print` / `end`），所以同一套解释器既能「直接跑完出结果」，也能「一个事件一帧地喂给动画」，两种模式共用一份代码。
